General

archive.org credentials

Optional — only needed for restricted items.
Public collections need no keys. For restricted items, the surest route is to be logged in to archive.org in this browser (downloads use your session). Keys here are exported to credentials.json for the app; grab yours from your S3 login page at archive.org/account/s3.php.

GitHub access token

Optional — lifts the update-check rate limit. GitHub allows only ~60 checks/hour per IP without a token, which shows as “latest release: rate-limited — try again later” on the Emulators and Apps tabs. A classic token with no scopes (public read only) is enough. Create one at github.com/settings/tokens. Stored only on this PC and sent only to api.github.com.

App Utility updates

Emulator update sources

Point each emulator at the GitHub repository whose Releases hold its Switch build (owner/name). When that app is installed, the Emulators tab compares the installed version against the latest release and offers a one-click update. Leave blank to skip the check for that app. Only add repositories you trust — the update downloads and installs whatever .nro that release ships. The optional asset box is a lowercase substring to pick the right file when a release has several .nro assets.

App update sources

The same idea as emulators, for every other homebrew app: point a .nro at the GitHub repository (owner/name) whose Releases hold its Switch build, and the Apps tab checks installed copies for updates. Entries tagged catalog are unverified suggestions from the bundled list — confirm each is the real project before updating, since the update installs whatever .nro that release ships. Only add repositories you trust.
